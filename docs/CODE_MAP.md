# Карта проекта: где что лежит

Короткий путеводитель, чтобы быстро найти нужный кусок кода.

## Быстрый поиск

| Что нужно поправить | Где искать |
|---|---|
| Текст, кнопка, блок на экране | `index.html` (разметка), затем `js/ui/*.js` (отрисовка) |
| Логика: что происходит при нажатии | `js/game/*.js` (поиск по имени метода: `grep -rn "имяМетода" js/`) |
| Внешний вид базовых элементов | `css/style/*.css` (порядок файлов важен, см. ниже) |
| Неоновая тема, фон, анимации | `css/neon/*.css` |
| Каталог скинов, предметов, кейсов | `js/skins.js`, `js/shop_items.js`, `js/shop_cases.js`, `js/cases_cb.js` (автоген) |
| Звуки | `js/sfx.js` (код), `sounds/*.wav` (файлы), `tools/sounds/` (генераторы) |
| Картинки | `img/` (см. раздел «Картинки») |
| Вход, регистрация, отправка сохранения на сервер | `js/auth.js` (клиент), `server.py` (сервер), `index.html` (форма `#auth-gate`) |
| Рейтинг КС | `js/ui/cs.js` (`csRatingHtml`, `loadRating`), `server.py` (`/api/leaderboard`) |
| Админ-панель: вкладки, карточка игрока, журнал | `admin.html`, `js/admin/*.js` (`editor.js` — карточка, `players.js` — список, `log.js` — журнал), `css/admin/admin.css`, API в `server.py` (`/api/admin/*`) |

## JavaScript

Объекты `Game` (логика) и `UI` (отрисовка) разбиты по файлам: каждый файл добавляет свои методы через `Object.assign`. Порядок подключения в `index.html` важен: сначала `game/core.js` и `ui/core.js`, которые создают объекты.

### Логика — `js/game/`

| Файл | Что внутри |
|---|---|
| `core.js` | состояние, роутинг по экранам, сохранение, обработчики событий (`bindEvents`) |

| `profile.js` | профиль: ник, трейд-ссылка, пополнение |
| `battle.js` | Battle: режимы, боты, старт баттла |
| `cs.js` | вывод предметов в КС, снаряжение и слоты |

## Сервер и аккаунты

- `server.py` — один файл на стандартной библиотеке Python: отдаёт статику и API.
  - `POST /api/register`, `POST /api/login`, `POST /api/logout`, `GET /api/me` — аккаунты. Токен входа в заголовке `Authorization: Bearer` (или `X-CB-Token`), пароль — scrypt. Cookie не используются (не работают во встроенном окне). `/api/login` и `/api/me` отдают роль (`player` или `admin`).
  - `GET /api/save` → `{save, version}`; `PUT /api/save` с заголовком `X-Save-Version` — сохранение игры целиком (объект из `saveGame`). При расхождении версии — `409`.
  - `GET /api/leaderboard` — топ-100 по `cs_value` (сумма цен `csInventory`, считается при сохранении). Только роль `player` и не заблокированные.
  - `/api/admin/*` — админ-API, см. раздел «Админ-панель» ниже.
  - Заблокированный аккаунт получает `403` на всех запросах; сессии при блокировке сохраняются.
  - Файлы `*.py` по HTTP не отдаются.
- `js/auth.js` — клиент: `Auth.start()` (вызывается из `game/boot.js`) проверяет вход, показывает форму
  или загружает сохранение и вызывает `Game.init()`. `Auth.queueSave(state)` вызывается из `saveGame` (`storage.js`).
  Сохранения уходят по одному за раз; `409` → сообщение и перезагрузка; `403` → форма входа с причиной.
- Сохранение в `localStorage` остаётся кэшем текущего аккаунта. После выхода ключ удаляется.
- База `accounts.db` — вне проекта (`../data/`), в архив проекта не попадает. Колонки `role`, `blocked`, `save_version` добавляются миграцией при запуске.
- Администратор создаётся только командой `python3 server.py create-admin <ник> <пароль>`.

## Админ-панель

- `admin.html` — отдельная страница, скрипты в `js/admin/` (`core.js` — вход, маршруты `#overview`, `#players`, `#player/<id>/<раздел>`, `#log`, окна подтверждения; `overview.js`, `players.js`, `editor.js`, `log.js`, `boot.js`). Стили — `css/admin/admin.css`.
- Скрипты игры для справочников (названия, цены, достижения, операция) подключаются в `admin.html` в том же порядке, что и в `index.html`.
- API (`server.py`, все требуют роль `admin`, иначе `403`; игроки-админы недоступны — `404`):
  - `GET /api/admin/stats` — метрики, регистрации за 14 дней, топ-10 по КС.
  - `GET /api/admin/players` — список (`q`, `status`, `sort`, `dir`, `page`, `per`).
  - `GET /api/admin/players/<id>` — `{player, save, version}`.
  - `PUT /api/admin/players/<id>/save` — правка сохранения (`{save, note}`, заголовок `X-Save-Version`, при расхождении `409`). Пишет в журнал список изменённых разделов.
  - `PATCH /api/admin/players/<id>` — ник, пароль (сброс завершает все входы), блокировка.
  - `DELETE /api/admin/players/<id>` — удаление.
  - `GET /api/admin/log` — журнал (`player`, `action`, `page`, `per`).
- Журнал (`admin_log`): время, администратор, игрок, действие, детали. Пароли, токены и сохранения в журнал не пишутся.
- Тесты: `tools/api_check.py` (API), `tools/admin_check.py` (браузер). Нужен администратор `MrRobbot`.

## Картинки

- `img/cases/<slug>_back.webp` и `<slug>_front.webp` — картинки кейсов (`front` опционален).
- `img/items/<id>.webp` — скины и предметы; `item_1.webp` — запасная картинка для пустых слотов.
- `img/shop/` — картинки магазина (WebP, со сжатием с потерями).
- `img/cs/` — картинки экрана КС.
- `img/battle/`, `img/bg/` — Battle и фоны (фон `bg_corridor.jpg`).
- `img/misc/logo.png` — логотип, не менять.

Кейсы (`img/cases/`), предметы (`img/items/`) и часть картинок `img/cs/` — WebP без потерь (пиксели идентичны исходным PNG).
Картинки магазина (`img/shop/`) — WebP со сжатием с потерями: исходные PNG удалены, восстановить их без потерь из проекта нельзя.
Логотип `img/misc/logo.png` и фоны (`img/bg/`, `img/battle/`, `img/cs/scene.jpg`) не конвертировались.

## Проверка изменений

Перед правкой сохрани эталон, после правки сравни. Сервер для проверки: `python3 serve.py` (порт 8000).

| Команда | Что проверяет |
|---|---|
| `python3 tools/smoke_test.py http://localhost:8000/index.html` | 7 экранов, навигация, кейс, продажа, апгрейд, контракт; ошибки страниц и консоли |
| `python3 tools/verify.py http://localhost:8000/index.html out_now` | 15 экранов: снимки и хэш вычисленных стилей каждого элемента |
| `python3 tools/api_check.py http://localhost:8000` | API: регистрация, версии сохранения (409), админ-методы, скрытие админа из рейтинга |
| `python3 tools/admin_check.py http://localhost:8000` | админ-панель в браузере: вход, список, баланс, инвентарь, статистика, достижения, операция, блокировка, журнал, удаление |
| `python3 tools/verify.py --diff out_before out_now` | сравнение двух прогонов `verify.py`: `IDENTICAL` или список расхождений |
| `python3 tools/hover_check.py <urlA> <urlB>` | состояния `:hover` интерактивных элементов в двух версиях |

Принцип: сначала эталон, потом правки, потом `--diff`. Если расхождение есть — смотри, какие элементы и свойства отличаются (`verify.py` печатает элементы и хэши; для подробностей открой оба прогона в браузере).

## Типичные правки

- **Новый предмет**: добавить запись в `js/skins.js` или `js/shop_items.js`, картинку положить в `img/items/<id>.webp`.
- **Новый элемент неона**: разметка в `index.html`, стили в нужном файле `css/neon/*.css` с префиксом `body.neon`.
- **Поправить базовый стиль компонента**: найти класс через `grep -rn "\.имяКласса" css/style/`, правка в том файле, где он стоит.
- **Новый звук**: файл в `sounds/`, вызов через `SFX` в `js/sfx.js` или в нужном месте `js/ui/*.js`.
