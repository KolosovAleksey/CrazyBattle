# CrazyBattle

Браузерная игра в стиле case-battle: открывай кейсы, апгрейдь предметы, подписывай контракты, продавай дроп.
Игра требует вход: регистрация по нику и паролю. Прогресс хранится на сервере (аккаунт),
в `localStorage` — только кэш текущего аккаунта. В рейтинге видны все зарегистрированные игроки
(кроме служебных аккаунтов администраторов).
Десктопная версия (мобильная не поддерживается).

### Как устроены скрипты

Разделы подключаются обычными `<script>` без модулей и сборщика. Объекты `Game` и `UI` создаются в
`game/core.js` и `ui/core.js`, а остальные файлы добавляют в них методы через `Object.assign`.
Порядок подключения задан в `index.html` и важен: сначала `core.js`, потом остальные разделы.
Админ-панель (`admin.html`) — отдельная страница со своими скриптами в `js/admin/`.

## Как запустить

Игре нужен сервер (аккаунты и сохранения), открыть `index.html` двойным кликом не получится:

```bash
cd case-drop
python3 server.py                # порт 8000
# открыть http://localhost:8000
```

Другой порт: `CB_PORT=8080 python3 server.py`.
Файл базы с аккаунтами по умолчанию — `../data/accounts.db` (вне папки проекта, чтобы аккаунты не попадали в архив проекта).
Другое место: `CB_DB=/путь/accounts.db python3 server.py`.

## Регистрация и вход

- Без входа игра не открывается. Регистрация: ник от 3 до 16 символов (буквы, цифры, `_`, `-`), пароль от 6 до 72 символов. Почта не нужна. Ники не повторяются без учёта регистра.
- Пароль хранится в виде хэша (scrypt), в открытом виде нигде не записывается.
- Вход сохраняется в браузере: токен лежит в `localStorage`, и при каждом визите срок продлевается. Пока не прошло 30 дней без визитов, пользователь не выходит из аккаунта.
- Вход работает и во встроенном окне на другом домене: cookie там браузеры не сохраняют, поэтому cookie не используются.
- Вход с одного адреса блокируется на 5 минут после 10 неудачных попыток.
- Выход: «Настройки» в профиле → «Выйти».
- Сброс пароля: сам игрок восстановить пароль не может (почты нет). Сбросить пароль может администратор в админ-панели; все старые входы при этом завершаются.

## Сохранение

- Сохранение игры отправляется на сервер через 1,5 с после изменения. При закрытии вкладки последние изменения тоже отправляются.
- После входа сохранение загружается с сервера, локальная копия заменяется ею. После выхода локальная копия удаляется.
- У каждого сохранения есть версия. Если администратор изменил аккаунт, версия меняется. Игра, которая продолжает отправлять старую версию, получает отказ (409), показывает сообщение и перезагружается, загружая правки администратора. Так устаревшая вкладка не затирает правки.

## Админ-панель

Администратор входит через обычное окно входа на сайте (`index.html`), и сразу открывается админ-панель (`admin.html`). Игра для администратора не запускается. Кнопка «Выйти» в админ-панели возвращает на окно входа сайта.

**Создание администратора.** Администратора нельзя создать через регистрацию на сайте. Его создаёт владелец сервера командой:

```bash
python3 server.py create-admin <ник> <пароль>
```

Если аккаунт с таким ником уже есть, команда назначает ему роль администратора и задаёт новый пароль.

**Что видит администратор и что может делать:**

- **Обзор** — число игроков, с сохранением, заблокированных, активных за сутки, суммы балансов и стоимость КС-инвентарей; график регистраций за 14 дней; топ-10 по стоимости КС.
- **Игроки** — все аккаунты игроков: поиск по нику, фильтр «активные / заблокированные», сортировка по колонкам, страницы по 25, 50 или 100.
- **Карточка игрока** (клик по строке):
  - *Общее* — имя профиля, подкрут и его множитель; смена ника, сброс пароля, блокировка и разблокировка, удаление аккаунта (с вводом ника для подтверждения);
  - *Баланс* — быстрые надбавки и списания, установка точного значения;
  - *Инвентарь* и *КС-инвентарь* — удалить предмет, удалить всё, выдать предмет из каталога (вариант и износ, цена из каталога);
  - *Статистика* — счётчики профиля и флаги;
  - *Достижения* — выдать или забрать каждое достижение, выдать или забрать все;
  - *Операция* — установить уровень от 0 до 100, сбросить операцию, посмотреть билеты;
  - *JSON* — полное сохранение: просмотр, применение, скачивание копии.
- **Журнал действий** — кто, с каким игроком и что сделал, когда. Фильтры по игроку и типу действия.

**Правила безопасности:**

- Блокировка — основной способ закрыть аккаунт. Удаление необратимо и требует ввода ника.
- Аккаунты администраторов не видны игрокам: их нет в рейтинге, в списке игроков и в карточках. По их идентификатору API тоже отвечает «не найдено».
- В журнале не пишутся пароли, токены и сами сохранения: только список изменённых разделов, суммы и комментарий администратора.
- Правка сохранения проверяет версию. Если игрок или другой администратор изменил аккаунт раньше, правка не применяется, карточка перечитывается.

## Рейтинг

- Рейтинг (вкладка КС → «Рейтинг») — топ-100 аккаунтов по стоимости выведенного в КС инвентаря.
- В рейтинге только зарегистрированные игроки. Ботов в рейтинге нет. Боты остаются соперниками в Battle.
- Заблокированные аккаунты и аккаунты администраторов в рейтинге не показываются.

**Ограничение:** сервер принимает сохранение от клиента как есть, поэтому значения в рейтинге
можно подделать, изменив данные в браузере. Честный рейтинг потребует, чтобы сервер сам вёл
открытие кейсов и выдачу предметов.

## Проверка

```bash
pip install playwright && python3 -m playwright install chromium
python3 server.py                                    # в другом окне, порт 8000
python3 tools/smoke_test.py http://localhost:8000/index.html   # игра
python3 tools/api_check.py http://localhost:8000               # API (нужен администратор MrRobbot)
python3 tools/admin_check.py http://localhost:8000             # админ-панель (нужен администратор MrRobbot)
```

`smoke_test.py` регистрирует временный аккаунт, проходит экраны, кейс, апгрейд, контракт и рейтинг.
Выводит ошибки JS и HTTP (`errors`, `http_errors`). Если они пустые, базовые сценарии работают.

`api_check.py` и `admin_check.py` проверяют API и админ-панель. Они создают тестового игрока и удаляют его в конце.
Для них нужен администратор с ником и паролем `MrRobbot`. Создайте его командой `create-admin` (см. выше).
Тестовые аккаунты игрока остаются в базе только при сбое проверки; их можно удалить вместе с базой.

Для рефакторинга (CSS, картинки, структура) есть два инструмента сравнения:

```bash
python3 tools/verify.py http://localhost:8000/index.html out_before   # эталон до правок (каждый прогон — новый временный аккаунт)
# ... правки ...
python3 tools/verify.py http://localhost:8000/index.html out_after
python3 tools/verify.py --diff out_before out_after                    # IDENTICAL — изменений нет
python3 tools/hover_check.py http://localhost:8000/index.html http://localhost:8001/index.html   # оба сервера с входом
```

`verify.py` сравнивает снимки и вычисленные стили каждого элемента на 15 экранах; `hover_check.py` сравнивает состояния при наведении.

## Звуки

Звуки генерируются скриптами из `tools/sounds/`:

```bash
python3 tools/sounds/gen_sfx.py      # создаёт звуки (см. ниже про case_fast)
python3 tools/sounds/gen_ticks.py    # перезаписывает case_tick, up_tick, up_tick_fast
```

Порядок важен: `gen_ticks.py` перезаписывает четыре звука, которые создаёт `gen_sfx.py`.
`gen_sfx.py` также создаёт `case_fast.wav`, но он не используется в игре: после генерации удалите его из `sounds/`.

## Сброс прогресса

Игрок: из консоли браузера `clearSave(); location.reload();` — сбрасывает только локальную копию. Серверное сохранение
восстановит её при следующем входе. Администратор: в карточке игрока вкладка «Общее» → «Удалить аккаунт»
или, на уровне базы, удалить аккаунт из `accounts.db`.
